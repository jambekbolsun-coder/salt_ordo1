# Salt Ordo — завершение production hardening

Дата проверки: 4 октября 2026. Базовый commit: `f60afe28866941d37e07db64a2d2f598cd2dec95`. Основная реализация: `f45525c40646198dc283fbe86dc7c38c20cd50c0`; заключительный commit содержит этот отчёт, безопасный повтор GET после 429 и уточнение текста cookies.

## Реализовано

- Подготовлены GA4, Meta Pixel и серверный Conversions API: отдельные категории согласия, общие event ID, ограниченные повторы и дедупликация, отсутствие Purchase при заявке. Без настоящих Environment Variables сервисы не активируются.
- Дополнена рекламная атрибуция клиента, обращения и заказа; UTM term, landing page, ID/названия кампаний, групп и объявлений; фильтры и отчёты по полученным данным. Нет выдуманных расходов, ROI или ROAS.
- Добровольное подключение TOTP, проверка кода, защищённое отключение, ротация сессии и управление собственными сессиями. После подключения MFA проверяется и сервером, и SQL-проверками ролей; прямой доступ к Supabase не обходит MFA.
- Health-check, структурированные обезличенные ошибки, необязательный HTTPS webhook мониторинга. Клиенту больше не передаются исходные ошибки административного proxy.
- GitHub Actions: lock-file install, lint, тесты, изолированные SQL-миграции, build, проверка секретов в истории/bundle, audit зависимостей. Никаких production credentials в тестах.
- CSV экспорт получает строки пакетами без повторного дорогостоящего подсчёта всей выборки. GET после 429 повторяется один раз с учётом Retry-After; записи автоматически не повторяются.

Полный список файлов: [PRODUCTION-HARDENING-FILES.txt](PRODUCTION-HARDENING-FILES.txt). Переменные, процедуры и мобильный чек-лист: [OPERATIONS.md](OPERATIONS.md). Резервирование: [BACKUP-RESTORE.md](BACKUP-RESTORE.md).
